Native ESSL compiler candidate

Enable `THREECPP_NATIVE_ESSL` together with the existing Vulkan target to build the fixed native frontend. CMake 3.24+ and Python 3.8+ are required. The existing `VulkanShaderCompiler::compile(vertex, fragment)` CLI path remains unchanged. Native compilation uses `VulkanShaderCompiler::compileESSL(VulkanEsslSourcePair)` and requires no CLI instance.

This candidate requires the VulkanShaderInterface revision that exposes `Array::strides` and reflects every array dimension. Rebuild all consumers of this public struct together. No binary from an earlier struct layout is compatible.

The input pair consists of unchanged original ESSL source strings and optional diagnostic names. Parse and link occur in the original language before AST mutation. The result owns SPIR-V, independent validator diagnostics, original linked-AST active uniforms/attributes, emitted mappings, per-stage interfaces and private backend scalar layouts. No AST or third-party pointer escapes compilation. All calls through the library serialize glslang initialization and AST use; this does not coordinate unrelated users of glslang's global lifecycle.

Original active reflection is glslang reflection and can include builtin vertex inputs. Attribute mappings distinguish buffer locations from SPIR-V builtins. Uniform mappings preserve the source name, root name and remaining nested/array path. `rootLayout` is that source uniform's root member tree, a leaf for scalar/matrix, not a complete UBO. Allocate a block buffer using `interfaces[stage].descriptors(set,binding).block`; resolve values with rootName+memberPath and reflected offsets/strides. Do not pass a leaf rootLayout to VulkanUniformBuffer's block constructor. The complete per-stage SPIR-V interfaces are retained for descriptor and pipeline layout consumers.

The private `threecppBackendBaseInstance` int32 and `threecppBackendFramebufferHeight` float32 report actual descriptor set/binding, byte offset, size and declared/used stage masks. They never appear in original active uniform reflection. A stage with no emitted uniform block does not declare these fields; an absent offset is UINT32_MAX. Material uniforms change their offsets, so the renderer must not assume 0/4.

The renderer contract is the frozen portable main wrapper: call original main, then negate final gl_Position.y and convert z to (z+w)/2. Original early returns and intermediate position reads retain their meaning. Use a positive-height Vulkan viewport with top=framebufferHeight-glViewportY-glViewportHeight and matching raster front-face convention. Supply actual firstInstance and framebuffer height. InstanceID reads become InstanceIndex-firstInstance; VertexIndex remains unchanged. FragCoord.y becomes framebufferHeight-y. dFdy results are negated; dFdx/fwidth remain unchanged. Vulkan 1.0 SPIR-V is independently validated.

Dependencies are fixed in `cmake/essl/dependency-lock.json`: official glslang/SPIRV-Tools/SPIRV-Headers commits, ZIP SHA256, complete extracted source hashes, exact dependency patches and license hashes. The glslang dependency is an explicit three-file fork for inactive extension function names. SPIRV-Tools has a separate two-file CMake-only patch that keeps Python codegen bytecode outside source trees; validator source is unchanged. The build verifies content before/after applying both patches. It rejects unverified FetchContent source-directory overrides and verifies bundled licenses. `THREECPP_ESSL_ARCHIVE_DIR` optionally supplies the exact ZIP files offline. Source dependencies are built locally; no imported host library or hardcoded machine path is used. The global `SPIRV-Tools-static` target and `threecpp::spirv_validator` alias are available to native validation tests.

External acceptance retained 25 successful exact material source pairs and the original invalid RawShaderMaterial default, nine development pairs, 68 independently validated modules per configuration, 19,961 existing binary/layout checks, 674 new independent mapping assertions, direct equality of every original JSON field and byte equality of all modules against the frozen portable prototype. Thirteen actual GL/Vulkan development framebuffer cases compared 17,280 channels with maximum difference zero in Debug and Release. Eight callers made 24 serialized repeated compilations without binary drift; original invalid-source/user-UBO/NUL rejection and the original 450 path were exercised. These are finite Windows/NVIDIA fixtures, not general semantic proof.

Programs/Program dispatch into this entry, material/resource uploads, descriptors, textures, vertex input and full renderer integration remain work. The captured material pairs provide compilation/layout evidence only. PointCoord, arbitrary extensions/stages, full active-pruning/location behavior, transform feedback, multisample/sample positions, arbitrary depth writes and clip precision remain unverified. User UBOs and mixed opaque structs are explicitly rejected. Fine/coarse dFdy forms lack a separate driver fixture. The retained corpus covers ESSL300; other ES versions and other platforms/drivers are unproven. Missing original gl_Position and non-ES profiles are rejected. Failures report linked=false, phase and diagnostics.

The patch must first be applied with `git -c core.autocrlf=false apply` so Git does not convert new hash-locked patch/license files before their scoped attributes are installed. Later checkouts preserve these raw bytes through scoped .gitattributes. A real core.autocrlf=true repository and fresh checkout were tested; plain initial apply without the command-level setting changed bytes and failed dependency guards.

With tests enabled, test/native-essl registers CPU compile/mapping/lifecycle and the 20-case frontend tests. Windows additionally builds both native GPU fixture sources and registers the 13-case native GL/Vulkan comparison. This fixture uses test-only fixed builtin resources; it does not prove material uploads. Set THREECPP_ESSL_CAPTURE_DIRECTORY to the pinned 26-pair Programs capture corpus to register the optional 25-valid/one-invalid material source and binary audit. The manifest hash is checked before the corpus runs. Test sources and CMake contain no local stage path; output folders distinguish configurations and tests. The external 68-module byte/JSON equality evidence remains separate and unchanged.
